# 创建决策 Spike

Spike 用有界实验回答一个当前无法从 Spec 或已确认页面合同判定的决策问题，产出可复核的结论和交接。Spike 不修改 Spec、ADR 或产品实现。

## 1. 触发与授权

- 只有用户或宿主明确要求创建、执行或继续 Spike 时才启动本 Skill；未知项、实现障碍或验证缺口不自动触发。
- 实施过程中出现未知项时，由宿主决定是否进入 Spike；implementation worker 只报告未知项，不自行创建或执行 Spike。
- 未获得明确授权时，不修改 Spec、ADR、任务账本或产品实现，不执行需要外部账号或真实生产资源的实验。

## 2. 界定决策问题

- 一个 Spike 只回答一个有界决策问题；先写下要决定什么、GO 条件、NO-GO 条件和非目标。
- 决策问题变化时新建 Spike 文档，不在旧文档无限追加。
- 无法预先定义 GO/NO-GO 判定门的问题不进入实验，返回宿主重新界定。

## 3. 建立实验边界

- 记录环境与输入、允许操作、禁止操作、停止条件与资源清理要求。
- 敏感数据（cookie、Authorization、签名 URL、账户信息）只保留定位所需的最小脱敏片段；证据位置固定，原始证据不散落在临时目录。

## 4. 执行实验方法

- 按顺序记录最小实验步骤、观察窗口和证据采集方式。
- 逐项执行并采集证据，不跳过步骤，不把未执行步骤报告为已执行。

## 5. 记录实验结果

- 使用 [Spike 模板](assets/spike-template.md) 第 4 节的结果表记录实验结果；表格列以模板为准，本 Skill 不重复其格式定义。
- 原始证据保留在稳定位置（session、Orca Task、已提交证据），文档只保留引用和结论。

## 6. 判定结论

- 结论只使用 GO、NO-GO 或 INCONCLUSIVE，并与第 2 节预先定义的判定门一致。
- 区分已确认事实与推断，列出推断依据和剩余未知项；证据不足时如实报告 INCONCLUSIVE。

## 7. 交接

- 列出需要宿主决定的事项，以及建议路由：继续实施 / 新 Spike / 更新 Spec / 创建 ADR。
- 清理实验产生的临时资源，保留不可重建的证据并说明位置。

## 8. 文档与交付

- 写入 `docs/spikes/YYYY-MM-DD-<topic>.md`；标题、导语与七节结构以 [Spike 模板](assets/spike-template.md) 为准。
- 使用模板书写时删除不适用字段，不保留空占位。

## 9. Spike 交付前检查

- 交付前逐项完成 [Spike 模板](assets/spike-template.md) 第 7 节的 Spike 交付前检查；检查清单以模板为唯一权威，本 Skill 不重复其内容。
- 检查未通过时停止交付，回到对应章节补齐后再检查。

完成条件：Spike 文档位于 `docs/spikes/`，按模板七节结构完整，结论明确（GO/NO-GO/INCONCLUSIVE），模板第 7 节检查全部通过，交接包含路由建议和剩余风险。
